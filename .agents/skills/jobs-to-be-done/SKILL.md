---
name: tramuri-jobs-to-be-done
description: Express a user job as an outcome-oriented hypothesis.
---

## When to use
Clarify the progress a user seeks when the user, context or underlying need is
unclear from the initial idea.

## When not to use
Do not force a Jobs to Be Done statement when the problem and user need are
already specific or when evidence is too thin to describe a job as a fact.

## Inputs
User and problem hypotheses, available context, alternatives and evidence.

## Process
Describe the situation, motivation, desired progress and current alternatives.
Keep observed statements separate from inferred job language and identify what
would validate the hypothesis.

## Output contract
Return a concise job statement, context, desired progress, evidence class and
validation need.

## Quality checklist
- [ ] The job describes progress rather than a feature.
- [ ] Context and user are explicit.
- [ ] Inferences are labeled as hypotheses.
- [ ] No interview or user quote is fabricated.
